# math-primary4-question 1.0.0

小学四年级作业/试卷题目；保持原题型条件，固定动作仍须源哈希门控。正文见resources.json。仅离线验证。

## math-detect-rules

【数学分栏题特别提醒】
1. 应用题/图形题的大题条件常在左栏底部，后续 (2)(3) 小题可能排在右栏顶部；右栏小题必须继承左栏同一大题的 parent_group_id 与 parent_stem_excerpt。
2. 若同页已出现 N-1，随后出现「(2)当……」这类小题，应优先编号为 N-2，而不是 auto-*。
3. 对所有数学题都必须输出 is_application_major_problem。应用题大题（非填空题）及其子题填 true；看图填空、表格填空、公式填空、括号内填空（如“m=( )”“( )元”）即使有生活情境或图表条件也填 false；口算、化简、选择、判断、纯单位换算或纯表达式练习填 false。

## math-grade-rules

【数学评分细则】
1. 先结合题目真实要求、学生最终手写和参考答案判断，不要只看数值等价，也不要因为题干出现“多少/单位/过程”等词就自动降分。
2. 所有应用题大题（非填空题）均要检查最终答话：学生只有算式、数字、式子或中间过程，缺少最终答话时，通常不应判 correct。即使小题要求“用含有字母的式子表示”“结果各是多少”等，只要它隶属于应用题大题且不是填空题，也适用本规则；但独立填空、看图填空、表格填空、公式填空、括号内填空等填空式题目，以及口算、化简、选择或判断题不因缺答话扣分。
3. 必须先读取题目清单中的 final_unit_requirement，并严格区分“计算过程”和“答：……”两个区域：
   - required：普通应用题的最终答话需有与题意兼容的单位；缺单位通常 partial，单位不兼容通常 wrong。
   - forbidden：典型为“当 x=...时”代入求式子的值，仅表示含字母式子代入求值时，计算过程末值必须写成纯数，不得在该数值后加括号单位；数值正确但过程末值加了单位通常 partial。它绝不禁止“答：……”中的单位、量词或“倍”等关系词；最终答话中的数量仍须写与题意兼容的单位，例如过程写“=300”，答话写“平均每月生产300个”。
   - optional：单位不是本题评分点，加或不加都不单独扣分。
   若题型本身只填数字，或单位已在括号/表头中给出，通常为 optional，不因学生未重复写单位扣分。
   识别涂改时只保留学生最终有效笔迹：若计算结果后的“(米)”等括号单位已被横线、斜线或涂抹明确删除，student_answer 只转写保留下来的数值，不得把被删除单位用于扣分。
4. 只要学生最终答案是代数表达式，必须先独立化简/规范化，检查是否仍有可完成的常数运算或可合并同类项；不得把学生未化简式原样抄入 correct_answer 后直接判 correct。随后结合题型决定最终形式是否属于评分点：
   - 题目求最终数量、差、和、结果，或要求填写最终答案时，应给出与当前学段相符的规范化结果。例如“上午比下午多卖多少元”中，50a-30a 应化简为 20a；思路正确但未化简通常判 partial，correct_answer 填 20a，error_type 填 final_form_required。
   - 题目要求“列式”或“用含有字母的式子表示”时，只要式子准确表达数量关系，不强制展开、因式分解或改变结构；如 3(b+50)、12(a-b)、(m-n)÷5 可保持原形式。
   - 题目明确要求“化简/最简/约分/展开/因式分解/指定形式”时，必须满足该形式；等值但未达到要求的答案通常判 partial。
5. 题目要求“用指定方法/写出过程/运算律或性质名称”时，过程、方法或术语完整性属于评分点；若题目只问结果，不强行要求过程或术语。

## math-pass1-grade-transcription-lock
【数学手写转写冻结规则（最高优先级）】
本规则只约束 student_answer 的视觉转写；你仍须正常理解题意、求出 correct_answer，并给出 verdict、understanding、error_type 等正式批改字段，不能退化为只做纯转写。
1. 必须先在不阅读题意、不求解、不看相邻答案的状态下，只根据图中学生黑笔有效笔迹冻结 student_answer；冻结后再独立理解、求解和判分。求解后不得回头重读或改写 student_answer。
2. 禁止按数学常识、题意、标准答案、印刷内容、相邻小题或后续步骤纠正、补全、交换、化简学生笔迹；数学常识只能用于 correct_answer 和 verdict。
3. student_answer 只记录学生写入答题空白、括号或解答区的黑笔内容；不得复制等号左侧、题干算式、单位等任何印刷内容，也不得把“印刷题干=学生填空”拼成完整等式。
4. 原样保留可见字符的重复、先后次序、运算符、上下标和大小写。若可见黑笔是连续两个 m，student_answer 只能写成 mm，不得改成 m²；只有图中确有与主体基线分离、位于右上角的清晰黑笔数字 2 时才能转写为 m²。若可见黑笔是 360÷a，必须保留为 360÷a，不得因题意或后续答案改写成 a÷6。
5. “结合上下文应该是……”“学生意图是……”“为了使等式成立……”“常见写法是……”均是违规推理。视觉候选与数学答案冲突时，以视觉候选为 student_answer，并在 verdict 中判错；不得消除这种冲突。
6. 视觉存在歧义时，保留能确认的可见字符并用 ? 标记疑点，同时降低 recognition_confidence 或设为 uncertain；不得在多个候选中优先选择数学上正确、常见或能与后续步骤吻合的写法。若两个候选的视觉证据相当而其中一个数学上正确，仍不得选择该正确候选，必须保留 ?。
7. 每题必须先输出 visual_answer_segments：按阅读顺序逐空列出“学生新增的黑笔字形”，一空一项，不含任何印刷字符；student_answer 必须只是这些片段的原样串联，不得出现 visual_answer_segments 中没有的字符或规范化写法。该审计字段只用于锁定证据，不替代后续理解与判分。
8. 例如印刷的 m×m= 后由学生黑笔写入 mm，则 visual_answer_segments 为 ["mm"]、student_answer 为 "mm"，不得含印刷的 m×m=，也不得写成 m²；印刷的 b= 后由学生写入 360÷a，则两字段只能记录 360÷a。
9. 学生原写法即使明显错误、不完整、不合常理，也必须保留在 student_answer；应通过 correct_answer、verdict、understanding 和 error_type 说明错误，严禁污染原始转写。

## math-pass1-grade-user-audit


【数学本页提交前强制审计】
逐题按以下不可逆顺序工作，但仍一次性输出正式批改 JSON：
A. 只看 position 对应的答题区域，把学生逐空新增的黑笔字形填入 visual_answer_segments；不抄印刷题干或等号左侧。
B. 把 visual_answer_segments 原样串联为 student_answer 后立即冻结这两个字段；二者必须字符一致。此后题意、求解结果、相邻小题和数学常识都没有权限修改它们。
C. 使用题意生成 correct_answer，并把它与已冻结的 student_answer 比较来生成 verdict；二者允许且应当冲突。
输出前删除所有源于“应该、意图、常见写法、为了成立、结合上下文”的转写修正。可见连续 mm 就保留 mm；可见 360÷a 就保留 360÷a。若确实看不清，写带 ? 的视觉转写并降低置信度，绝不能用正确答案消除问号。

## math-operation-law-full-name-grade-rules

【本页含运算律名称填空：完整术语专项核验】
1. 本规则只用于要求填写、判断或说明“运用了什么律/运算律/性质名称”的小题；只要求写字母公式、变形算式或计算结果的题不适用。
2. correct_answer 必须使用由运算符和变形方式确定的规范完整名称：乘法题写“乘法交换律”或“乘法结合律”，加法题写“加法交换律”或“加法结合律”，不得把 correct_answer 缩写成“交换律”“结合律”“交换”“结合”。多个规律并列时可写“乘法交换律和乘法结合律”，或在不产生歧义时写“乘法交换律和结合律”。
3. 学生只写“结合律/结合”或“交换律/交换”，缺少“乘法/加法”这一运算类别时，不得按同义、省略或结合题意视为完整正确；其余槽位正确时整题通常判 partial，error_type 写 operation_law_name_incomplete。
4. 必须区分学生手写与题干印刷字。若空格后已印有“律”，学生在空内只写“结合”，页面拼接后虽显示“结合律”，仍缺少“乘法/加法”；不得把印刷的“律”当成学生多写了一字，更不得替学生补出“乘法/加法”。
5. 例如“35×125×8 可以运用（ ）律，先算（ ）”：规范答案是“乘法结合律，125×8”。学生写“结合/结合律，125×8”时，第二空正确但第一空术语不完整，必须判 partial，不能判 correct。

## math-verification-suffix

【验算要求】
1. 对每道计算题，请先识别学生作答内容，再自行独立计算出正确答案。
2. 将你的计算结果与学生答案逐位对比，确认是否一致。
3. 若不一致，在 error_type 中具体说明错误环节（如"进位遗漏"、"退位错误"、"乘法口诀记错"等）。
4. 对应用题，请先理解题意、列出算式，再计算结果；correct_answer 填写最终数值。
5. 学生答案为代数表达式时，必须独立化简/规范化后再判断，并把与题意匹配的标准形式写入 correct_answer；不得把学生式子原样复制为 correct_answer 后直接判对。
6. 求最终数量、差、和、结果或填写最终答案时，仍有可完成运算或可合并同类项通常不得判 correct；例如 50a-30a 应化简为 20a，思路正确但未化简时判 partial，error_type 填 final_form_required。若题目仅要求列式或“用含有字母的式子表示”，则不强制展开或改变能准确表达数量关系的结构。
7. 你的计算过程请在思考中完成，最终输出仅包含 JSON，不输出任何 Markdown 或其他内容。

## -uncertain-rules[math]

【uncertain 触发条件（数学）】
以下情形必须将 verdict 设为 "uncertain"，不要强行给出 correct/wrong：
1. 画图/画线/涂色/操作类题目（无法判断图形正确性）。
2. 题干或选项因图片截断而不完整。
3. 应用题答案需要阅读材料但材料不在本页。
4. 学生答案字迹完全无法辨认（≥50% 区域模糊）。

## -subject-hints[math]
请仔细复算每道计算题，给出你认为的 correct_answer；若无法确定则填 null。转写时区分印刷题干与手写演算；已划掉的算式不要写进 student_answer。若数字后的括号单位被横线、斜线或涂抹明确删除，只保留未删除的数字，不得转写已作废单位。
